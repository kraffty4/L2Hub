# AGENTS.md — L2Hub

L2Hub — личный лаунчер локальных серверов Lineage II: одной кнопкой поднять сервер нужной хроники и запустить клиент, играть одному или с друзьями. Проект для автора и пары его друзей, а не публичный сервис.

## 1. Состояние

Фаза 2: лаунчер (`launcher/`) работает с High Five (с модами), Gracia Final, Interlude и Gracia Epilogue (у обеих — фантомы и моды H5, `docs/INTERLUDE.md`, `docs/EPILOGUE.md`). Версия — в `launcher/l2hub/__init__.py`, история — `CHANGELOG.md`. Запуск и проверка — `README.md`, раздел «Запуск». План, архитектура и открытые вопросы — `docs/PLAN.md`, карта хроник и сборок — `docs/CHRONICLES.md`. Решения, принятые автором, фиксировать в `docs/PLAN.md` (раздел «Решения») с датой.

## 3. Правила

- Пути внутри проекта — ASCII без пробелов: Java, Ant и MariaDB плохо переносят кириллицу и пробелы.
- Оригиналы автора (La2offline, клиенты) не менять. Патчить копию или делать бэкап, способ отката записывать.
- Любое скачивание — только с согласия автора: что, откуда, какой размер. Особенно патченные `system` клиентов от комьюнити: это непроверенные бинарники. Скачанное класть в `downloads/` и распаковывать в отдельную пустую папку.
- Клиенты и ассеты NCSoft не класть в репозиторий и никуда не выкладывать. Публичный сервер и монетизация не цель проекта.
- Место: C: — быстрый, но тесный; E: — медленный внешний HDD для архива. Где держать клиенты, решает автор. С 2026-10-23 на C: только клиент High Five: на нём первым делом проверяются новые моды. Остальные клиенты — на E: под прежними путями (`AGENTS.local.md`), они грузятся медленнее.
- Одновременно работает один профиль: порты логина и гейм-сервера у всех профилей общие.
- Лаунчер: ядро (`l2hub/servers.py`, `health.py`, `configs.py`) не зависит от окна. Любую правку ядра сначала проверять через `python -m l2hub.cli`, интерфейс — через `python -m l2hub.devserver` в браузере. В объекте `Api` не держать публичных полей с объектами pywebview или .NET: pywebview обходит публичные поля при генерации JS-обвязки (окно — в `_window`).
- Программа и данные (с 0.4.13): `paths.APP` — ресурсы программы, `paths.HOME` — данные; из исходников HOME — всегда корень репозитория, другой — только переменной `L2HUB_HOME`. Мастер установки, импорт сборок и всё, что ставит хроники с нуля, проверять на отдельной папке данных (`L2HUB_HOME=<рабочая папка>\L2Hub_rttest`, окно — `l2hub-devserver-fresh` в `.claude/launch.json`), а не на данных автора; база и сервер там — на тех же портах, под замком.
- Сборка сервера из Python — `l2hub/builder.py` (`cli fetch|build|setup|dbinit`): патчи накладывает сам, байт в байт, без git; «Пересобрать» в окне — через него. Новый вид своей сборки — запись в `bundles.json`, а не код под одну сборку (решение автора 2026-10-21). У одной хроники может быть несколько серверов: профиль с `"chronicle": "<id>"` — вариант (`c4_lisvus` рядом с `c4`).
- Параллельные сессии делят порты и коммиты через `data/agents/lock.py` (`take ports|commit … --wait 540`, `free`, `status`): в замке очередь, продлить порты при выключенном сервере, пока другие ждут, нельзя.
- Сервер, поднятый из консоли агента (`l2hub.cli start` из Claude Code в приложении Claude), входит в дерево процессов приложения, и обновление или перезапуск приложения гасит его целиком. 2026-10-19 так гейм успел сохраниться, MariaDB была убита (на следующем старте — crash recovery без потерь), а логин, клиент и мозги закрылись без следа в логах. Из консоли агента сервер поднимать только для проверок; для игры его запускает автор из окна лаунчера.
- Исходники Mobius в `servers/` не в git. Любая наша правка исходников — только вместе с патчем в `patches/<id>/` или в модуле `phantoms/`, иначе она потеряется при обновлении сборки.
- Фантомы (с 2026-10-20): код и конфиги правятся в `phantoms/core/`, данные хроники — в `phantoms/<id>/dist/`, а не в `servers/`: `server_build.ps1` копирует модуль в исходники и затирает правки там (затёртое сохраняет в `servers/<id>/.module_overwritten/` с предупреждением). Врезки в файлы Mobius правятся в дереве `servers/<id>/<сборка>/`, после чего `python -X utf8 tools/phantoms_glue.py <id>` пересобирает `phantoms/<id>/glue.patch` и проверяет, что с нуля получается то же дерево байт в байт; `--check` — только проверка. Новая хроника для фантомов — `phantoms/<id>/` со своими `base.json`, `dist/` и `glue.patch` (см. `phantoms/README.md`).
- Переводы строк в исходниках Mobius вперемешку (CRLF и LF): сохранять перевод строк каждого файла. Патч с LF-строками, наложенный `git apply` на CRLF-файл, переписывает в LF весь файл (так было с `0001` до 2026-10-20) — патчи к CRLF-файлам держать в CRLF; `phantoms_glue.py` так и пишет. `grep` в Git Bash врёт про CR (и срезает, и находит лишнее) — проверять байтами (Python, `od`). Скрипты `data/scripts` сервер компилирует при старте против ядра: меняя API ядра, искать его использования и в `dist` (`rg -uu`), иначе в логе появится `Failed to execute script list!`, а подробности — в `log/error0.log`.
- C4 — L2Solo (`servers/c4`, git-клон их репозитория, `docs/L2SOLO.md`): их код не патчить и в наш репозиторий не класть. Обновление — `git pull` и `npm install --ignore-scripts`, всё своё — через слой настроек и профиль `profiles/c4.json`.
- В git — ничего личного автора: пути его машины, ники персонажей, имена друзей, адреса. В доках — метки из `AGENTS.local.md` (`<игры>\LA2 H5`, `<загрузки>\…`), сами пути, имена и адреса — там (решение автора 2026-10-22: публичный репозиторий).
- Перед правкой смотреть `git status` и не трогать чужие незакоммиченные изменения. Коммиты — по просьбе автора.
- Версии: `0.<готовых хроник из списка 1.0>.<номер коммита>` (схема — `docs/PLAN.md`, «Решения», 2026-10-18). Каждый коммит делается так:
  1. +1 к третьей цифре `__version__` в `launcher/l2hub/__init__.py` (больше нигде версию не писать: `pyproject.toml` держит `"0"`, окно берёт версию через `Api.version()`);
  2. строка в `CHANGELOG.md`;
  3. после коммита — тег `vX.Y.Z` на него (`git tag -a`).

  Хроника из списка 1.0 стала готовой — +1 ко второй цифре, третья с 0, и отметка в `docs/CHRONICLES.md`.
- Насовсем ничего не удалять: мелочь — в Корзину, большое — в архив (см. глобальные заметки агентов).
- Документация и комментарии — по-русски; ключи конфигов, имена файлов и пути — как в источнике.
- Ключ API мозгов фейков (`data/brain/deepseek.key`) автор кладёт сам. Не просить его в чат, не печатать и не копировать; проверять только наличие и работу (`python -m l2hub.brain <id> --test …`).
- Фейков, напарников и охотников генерирует `tools/fake_players.py` (таблицы `PERSONAS`, `COMPANIONS`), их мозги — `launcher/l2hub/brain.py`. После правки таблиц — перегенерировать прямо в модуль для каждой хроники с фантомами (`python -X utf8 -I tools/fake_players.py servers/<id>/<сборка>/dist/game/data servers/<id>/server/game/data/geodata phantoms/<id>/dist/game/data`, сейчас `ct26_highfive`, `interlude`, `epilogue`, `classic_tales` и `ess_crow`) и прогнать `server_build.ps1`. Генератор детерминирован: без правки таблиц вывод совпадает байт в байт; грейды он берёт по датапаку, камаэлей там, где их нет, заменяет по `NO_KAMAEL`.
- Общение с автором — Pizdabol Edition по глобальным заметкам агентов.
