Проверка конкретного итогового GameServer.jar — 06.11.2026

Это проверка готового артефакта, не второй прогонщик мира. Для запуска мира
используется существующий tools/selftest_run.py; этот инструмент не открывает
БД, не поднимает Game/Login и не запускает клиент или L2Hub.

Python 3.12+ и JDK 27; пути задаются только аргументами:
python verify_final.py --final-jar <GameServer.jar> --game-data <game/data> --libs <server/libs> --expected-sha <sha256> --source-commit <40hex> --java-home <jdk27> --out <новый-каталог>
Инфраструктурная проверка отдельно: python verify_final.py --selftest --java-home <jdk27> --out <новый-каталог>

Запрошенные production helpers не компилируются. Проверяются 40 CodeSource,
ресурсов классов и SHA именно переданного JAR. Другие серверные JAR исключены,
обычные библиотеки проверяются на подмену классов. Testclasses создаются заново;
совпадение имени с production-классом или повторное использование каталога — отказ.

Изолирующие агенты существуют только в тестовой JVM: запрещают JDBC и заменяют
границы мира/акторов/пакетов. Установленному серверу эти агенты не нужны.
Проверяются текущий владелец помощника и пути 1323, восемь режимов заточек,
стабильность entryId, читатели восьми файлов реплик и реальный Controller.
Сетевые пакеты записываются в памяти: клиентский сериализатор, реальная оплата,
сохранение в БД, списание MP и бой игрока этим тестом не доказаны.

VERIFIED.json содержит результат именно native source ea1ff95. Первый запуск
теста неверно искал sceneAllowed/canBind прямо в tick; исправлена только проверка
ссылки invokedynamic на лямбду. Игровые классы и ограничения не ослаблялись.
Коммит сборки не зашит в JAR: нужна отдельная квитанция сборки и точный SHA.
Полная литературная переработка всего остатка банка не объявлена завершённой.
