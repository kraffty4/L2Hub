# Режим друзей: способы игры по сети

Сервер работает на ПК автора, друзья подключаются к нему через Radmin VPN. Выбор автора — 2026-10-18: Radmin бесплатный, без лимита игроков, проще всего для друзей. Запасной вариант, если через ретранслятор Radmin будет плохой пинг (друг в Японии), — ZeroTier.

## Способы (с 2026-10-20, раздел «Друзья»)

Решения автора 2026-10-20: способ один на все хроники; способы — Radmin VPN, Tailscale, ZeroTier, локальная сеть, а выделенный сервер — в планах.

| Способ | Как L2Hub находит адрес этого ПК | Что делают друзья |
|---|---|---|
| Только этот ПК | — (127.0.0.1) | не подключаются |
| Radmin VPN | адаптер с адресом из `26.0.0.0/8` | «Присоединиться к сети» по имени и паролю |
| Tailscale | адрес из `100.64.0.0/10` или адаптер Tailscale | входят по приглашению хоста |
| ZeroTier | адаптер ZeroTier | «Join New Network» по ID сети, хост одобряет |
| Локальная сеть | частный адрес (10, 172.16, 192.168) на настоящем адаптере: Wi-Fi, Ethernet (Hyper-V, WSL, Docker, виртуалки не в счёт) | тот же Wi-Fi или роутер |
| Выделенный сервер | в планах: сервер круглосуточно на арендованной машине; L2Hub пока поднимает сервер только на этом ПК | — |

Кнопка способа (`Api.set_network_all` → `network.apply` для каждой установленной хроники, кроме L2Solo) пишет в конфиги:
- **Mobius:** логин и гейм слушают `0.0.0.0`; `ipconfig.xml` — своему клиенту `127.0.0.1`, сети адаптера способа (подсеть по его маске, у Radmin `26.0.0.0/8`) и всем остальным — адрес этого ПК в ней.
- **La2offline (GF):** Hostname `*`, `ExternalHostname` = адрес способа. Клиентам из «внутренних» сетей (10, 172.16, 192.168, 127) L2J 2.0.6 отдаёт `InternalHostname` гейма: для частного адреса (локальная сеть, обычно ZeroTier) туда тоже пишется адрес, иначе — `*`, как в оригинале.

L2.ini и «клиент целиком» собираются для хроники, выбранной в «Для друзей», с адресом её способа; README в пакете — с первым шагом под этот способ (`friendpack.JOIN`). Старый режим «друзья по Radmin» в конфигах читается как Radmin VPN, ничего переключать не надо. Ниже — как это было устроено и проверено с Radmin.

## Как это устроено

В Radmin у каждого ПК свой адрес `26.x.x.x` (сеть `26.0.0.0/8`). Клиент сначала подключается к логину по адресу из своего `L2.ini`. Логин отдаёт ему адрес гейм-сервера, выбранный по адресу клиента.

Лаунчер (`launcher/l2hub/network.py`, вкладка «Друзья») переключает два режима и сохраняет их прямо в конфигах сервера:

| | «только этот ПК» | «друзья по Radmin» |
|---|---|---|
| логин и гейм слушают | `127.0.0.1` | все сети: `0.0.0.0` у Mobius, `*` у La2offline |
| адрес гейма для своего клиента | `127.0.0.1` | `127.0.0.1` |
| адрес гейма для клиента из Radmin | — | адрес этого ПК в Radmin |
| где это задаётся у Mobius (H5) | `login/config/Server.ini`, `game/config/Server.ini`, `game/config/ipconfig.xml` | то же, в `ipconfig.xml` добавляется подсеть `26.0.0.0/8` |
| где это задаётся у La2offline (GF) | `loginserver.properties`, `server.properties` (Hostname) | то же плюс `ExternalHostname` = адрес Radmin: L2J 2.0.6 отдаёт его всем клиентам не из 127/10/172.16/192.168 |

Перед каждой правкой — бэкап в `data/backups/config/<id>/`. Сервер читает конфиги при старте, поэтому новый режим работает после перезапуска. «Проверить всё» показывает режим и ругается, если режим друзей настроен на адрес Radmin, которого у ПК сейчас нет.

## L2.ini для друзей

Друзьям нужен их `L2.ini` с `ServerAddr` = адрес хоста в Radmin. Кнопка «Собрать L2.ini» делает его так:
1. берёт `L2.ini` клиента профиля;
2. меняет одну строку `ServerAddr`;
3. шифрует обратно ключом комьюнити;
4. кладёт в `data/friends/<id>/` вместе с `README.txt`.

Шифрование — `l2ini.encode()`. Приватная экспонента пары комьюнити взята из `l2encdec.exe` La2offline, сам exe не запускался (подробности — в описании `launcher/l2hub/l2ini.py`). Проверено на `L2.ini` обеих систем: перешифрованный файл расшифровывается байт в байт, длина та же; после смены адреса отличается ровно строка `ServerAddr`. Примет ли его настоящий `L2.exe`, не проверено: это часть репетиции ниже.

Друзьям нужен клиент той же хроники с той же системой, что у автора:
- H5 — R.C-TEAM Rev 273, язык Russia, `system_ru`;
- GF — `La2system`.

## Клиент целиком для друзей

Если у друга нет клиента, нажми «Собрать клиент целиком» (`launcher/l2hub/friendpack.py`, `l2hub.cli pack <id>`). Получится zip клиента профиля: `data/friends/<id>/<папка клиента>.zip`, например `LA2_H5.zip`. Прежний пакет уходит в Корзину. Работает только в режиме друзей: в пакет пишется адрес хоста в Radmin.

Что попадает в пакет:
- Все папки клиента, кроме чужих систем. Из систем берётся только та, из которой запускается клиент профиля: `system_ru` у H5, `La2system` у GF. Остальные папки с «system» в имени не берутся (`system`, `system_ncsoft`, `system_friendtest`).
- Папка системы в пакете называется так, как её ищет `L2.ini` клиента (`Paths=../<папка>/*.u`). У H5 автора клиент запускается из копии `system_ru`, но классы берёт из соседней `../System`. Поэтому в пакете содержимое `system_ru` (русский язык) лежит в папке `system`. Первая сборка клала её как `system_ru`, и клиент падал на первой текстуре (`Assertion failed … UClass::Bind`): классов движка он не находил. У GF `L2.ini` ищет классы в своей `La2system`, там имя не меняется.
- В папке системы — `L2.ini` с адресом хоста в Radmin.
- В корне — `README.txt` (шаги для друга) и `Play.bat` (запуск `L2.exe` из папки системы).

Что не попадает — личное и временное из папки системы: логи, `WindowsInfo.ini` (раскладка окон), `s_info.ini`, `L2CompiledShader.bin`, скриншоты. Сохранённых логинов в конфигах клиента нет, проверено.

Как жмётся: звуки, музыка и голос лежат без сжатия (почти не жмутся), остальное — deflate 1. Обычный zip Windows открывает без 7-Zip. Объёмы: H5 — 10,7 ГБ, 2023 файла; GF — 8,9 ГБ.

Передаёт архив автор сам: облако, флешка, торрент между своими. Клиенты NCSoft никуда не выкладываются.

Проверено 2026-10-18 на H5:
- архив 6,3 ГБ собран за 2 мин 21 с;
- CRC всех 2023 файлов совпали;
- из систем внутри только `system_ru`, личных и временных файлов нет, `ServerAddr` = адрес Radmin хоста;
- распакован в `data/friends/ct26_highfive/_test` за 66–84 с;
- `L2.exe` из распакованного пакета запустился, автор вошёл новым логином: аккаунт создался сам, последний IP в базе — адрес Radmin. Это после исправления папки системы, см. выше.

## Шаги

**Автор.**
1. Поставить Radmin VPN с [radmin-vpn.com](https://www.radmin-vpn.com/) и создать сеть (имя и пароль придумать самому).
2. В L2Hub: «Друзья» → «друзья по Radmin», перезапустить сервер.
3. При первом запуске Windows спросит про брандмауэр. Для H5 спрашивает `runtime\jdk-27\bin\java.exe`, для GF — `login_server.exe` и `game_server.exe`. Разрешить и для частных, и для общественных сетей: сеть Radmin Windows обычно считает общественной.
4. «Собрать L2.ini», отправить его друзьям вместе с именем и паролем сети Radmin.

**Друзья.**
1. Radmin VPN → «Присоединиться к сети» по имени и паролю.
2. Положить присланный `L2.ini` с заменой в папку системы клиента, свой сохранить рядом.
3. Войти: аккаунт создаётся сам при первом входе (`AutoCreateAccounts = True` у обеих хроник).

## Репетиция на одном ПК (без друзей)

Делается после установки Radmin:
1. Режим «друзья по Radmin», перезапуск. `netstat` должен показать логин и гейм на `0.0.0.0`, а не на `127.0.0.1`.
2. С этого же ПК открывается TCP-соединение на `26.x.x.x:2106` и на порт гейма.
3. «Собрать L2.ini». Проверка клиентом: копия папки системы (как `system_ru`), в неё — собранный `L2.ini`, запуск `L2.exe` из копии. Клиент идёт на логин по адресу Radmin, логин видит клиента из `26.0.0.0/8` и отдаёт гейм по адресу Radmin, то есть весь путь друга, кроме брандмауэра. Свой клиент при этом не трогается.

### Итог репетиции 2026-10-18 (High Five)

Адрес хоста в Radmin — `26.x.y.z`. Результаты:
- **Порты.** После режима «друзья по Radmin» и перезапуска логин и гейм слушают `0.0.0.0:2106` и `0.0.0.0:7777`. База, мозги и связка логин–гейм (9014) остались на `127.0.0.1`. По адресу Radmin оба порта отвечают.
- **Клиент друга.** Собранный `L2.ini` (`ServerAddr=26.x.y.z`) лежит в копии `system_ru` — `<игры>\LA2 H5\system_friendtest`. Клиент из этой копии принял файл, то есть шифрование верное. Автор вошёл в мир персонажем PlayerOne, а клиент держал соединение с геймом на `26.x.y.z:7777`: логин отдал клиенту из `26.0.0.0/8` адрес Radmin, как и задумано.
- **Брандмауэр.** Для `runtime\jdk-27\bin\java.exe` есть входящие правила «Разрешить» для частных и общественных сетей. Сеть Radmin у Windows общественная.

Чего репетиция не покрыла:
- Трафик с другого ПК через брандмауэр: с одного ПК он через брандмауэр не идёт. Правила на месте, проверка — в субботу.
- Gracia Final в режиме друзей. Для его `login_server.exe` и `game_server.exe` правил брандмауэра ещё нет, Windows спросит при первом запуске в режиме друзей.

Копия `system_friendtest` оставлена для будущих проверок; свою `system_ru` автора репетиция не трогала. Правила брандмауэра пускают Java и в сеть Wi-Fi (она тоже «общественная»): дома это не страшно, а в чужом Wi-Fi лучше переключиться на «только этот ПК».

## Если не пускает

- Логин не отвечает, у друга таймаут — брандмауэр Windows или друг не в той сети Radmin. В Radmin у хоста должен гореть зелёный значок друга.
- Логин пускает, сервер в списке есть, но вход в мир виснет — гейм отдаёт не тот адрес. Проверить «Проверить всё» → «Сеть» и `ipconfig.xml` (у GF — `ExternalHostname`).
- Пинг высокий — Radmin идёт через ретранслятор (у друга в Radmin соединение «через ретранслятор»). Тогда пробовать ZeroTier.
