# La2offline 4.0: разбор и что берём

Разбор 2026-10-17. Источники: формы Delphi из `La2offline.exe` (ресурсы `TFORM1–3`, разобраны в текст — `docs/design/la2offline/TFORM1_main_form.txt`), строки внутри exe, bat-файлы сервера и скриншоты окна от автора. Сам `La2offline.exe` агент не запускал: его остановка вызывает `taskkill /F /IM cmd.exe` и `java.exe` по всей системе, а у автора в это время работали консоли Claude и Codex.

## Что внутри

- Лаунчер — Delphi 2009 со скинами AlphaControls, автор jmaniac, сервер и датапак — RusTeam (`ru.rt.*`, L2J 2.0.6).
- Кнопки: Start/Stop MySql, Start/Stop Server, Kill All, Start/Stop WEB (встроенный сайт, `http.exe`).
- Вкладки:
  - **Сервер** — статусы Сайт/MySql/Login/Game и прогресс; «Показывать окно запуска» для гейма и логина; INET IP (Hamachi), LAN IP и IP в `L2.ini` клиента; кнопка «Помощник» (`Guide.exe`).
  - **Рейты** — XP, SP, PartyXP, PartySP, PetXP, SinEaterXp, Adena, Предметы, Манор, RaidDrop, Spoil, КвестДроп, КвестНаграда, Рыбалка; хербы: обычные, HP/MP, средние, большие, Special, Vitality.
  - **Основные** — все игроки админы; меню админа (la2offline или обычное); GM при входе бессмертен, невидим, герой; ограничения GM на предметы, скиллы, вес; стартовая адена; удаление персонажа через N дней; ПвП-зоны; анонс ПК; глобальный чат; мастер профессий; автоизучение скиллов; саб без квеста; сообщение в чате при входе; окно новостей при входе (`servnews.htm`).
  - **Особые** (нужен запущенный MySQL) — новые персонажи в центре Гирана или в стартовом городе; выдать и забрать права админа по имени персонажа; список админов.
- Как работает:
  - MySQL — `server\mysql-la2.exe --console` (MySQL в песочнице ThinApp);
  - логин и гейм — переименованная Java 6: `login_server.exe` и `game_server.exe` с аргументами из `startLoginServer.bat` и `startGameServer.bat`;
  - статусы — TCP-подключение к портам по таймеру (Indy `TIdTCPClient`);
  - настройки пишутся прямо в `loginserver.properties`, `server.properties`, `rates.properties`, `General.properties`, `Character.properties`, `servnews.htm`;
  - `L2.ini` клиента с нужным IP собирается через `data\encdec` (`l2encdec.exe`);
  - права админа — `UPDATE characters SET accesslevel=127 WHERE char_name='…'` склейкой строки (SQL-инъекция);
  - остановка и Kill All — `taskkill /F /IM` для `game_server.exe`, `login_server.exe`, `mysql-la2.exe`, `mysqld*.exe`, `http.exe`, а также для всех `java.exe`, всех `cmd.exe` и `utorrent.exe` в системе. Корректного сохранения нет.
- Оформление — официальный арт NCSoft (воин-лев на сплэше и вкладке «Сервер»). Для L2Hub чужой арт не берём.

## Что берём в L2Hub

| Из La2offline | Как у нас |
|---|---|
| Статус по компонентам (MySql, Login, Game) | Плитки «База, Логин, Гейм, Клиент» с портом, PID, памятью, онлайном и кнопка «Проверить всё» с подсказками |
| Раздельный старт базы и сервера | Меню у кнопки «Играть»: только сервер, только база, перезапуск гейма |
| «Показывать окно запуска» | «Показать консоль сервера» — живой лог |
| Рейты и «Основные» | Экран «Основное» с теми же группами, привязанный к настоящим ключам конфигов |
| — (не было) | «Все настройки» — каждый ключ всех конфигов сборки: поиск, «только изменённые», описание и умолчание из самих конфигов, сброс к умолчанию |
| LAN / INET (Hamachi) / L2.ini IP | «Клиент и сеть»: режим «этот ПК / LAN / VPN», адреса в `ipconfig.xml`, адрес в `L2.ini` правит лаунчер |
| Выдача прав админа | Права GM в «Сервисе», только пока персонаж офлайн, без склейки SQL |
| Стартовая локация новых персонажей | `CustomStartingLocation` в «Основном» |
| Сообщение и окно новостей при входе | `ScreenWelcomeMessage*` и `ShowServerNews` в «Основном» |

Не берём: `taskkill` по всей системе, склейку SQL, MySQL в ThinApp, официальный арт.

## Gracia Final в L2Hub

Второй лаунчер из нашего не запускается. Профиль `profiles/gracia_final.json` (`"type": "la2offline"`) работает с копией сервера La2offline и поднимает его части напрямую. Оригинальная папка La2offline остаётся нетронутой и рабочей сама по себе. Если найдётся живой эмулятор Gracia Final на современном коде, профиль можно переключить на него.

### Копия

2026-10-18 `La2offline 4\server` скопирован в `servers/gracia_final/server` целиком: 17 499 файлов, 267 МБ. Копия сверена с оригиналом (`diff -r`) — совпала. `La2offline.exe`, `data\` (в том числе `encdec`) и `web\` не копировались: лаунчеру они не нужны.

В копии лежит и база: MySQL 5.0.67 в песочнице ThinApp, данные — `server\DB\MySQL\%drive_C%\MySQL\Data`, база `l2rt`, таблицы InnoDB. Последняя запись в неё — 2026-07-04, тогда же последний запуск гейма по логу. PID-файл MySQL в папке данных — с другого ПК (`DESKTOP-G15RRBU.pid`): на этом ПК La2offline, похоже, не запускался.

### Порты

У La2offline свои порты, кроме логина. С MariaDB и High Five они не пересекаются:

| Часть | Порт |
|---|---|
| MySQL | 3305 |
| логин для клиента | 2106 (как у всех хроник) |
| логин для гейма | 9014 |
| гейм | 1042 |

### Как лаунчер запускает части

1. База — `server\mysql-la2.exe --port=3305 --bind-address=127.0.0.1`, рабочая папка `server`. Без `--console`, с которым её запускал La2offline: ошибки пишутся в `*.err` в папке данных. Остановка — `server\mysqladmin.exe --no-defaults -h 127.0.0.1 -P3305 -u root shutdown`. Пароля у root нет, поэтому база слушает только этот ПК.
2. Логин и гейм — встроенная Java 6 (32 бита): `server\jre\bin\login_server.exe` и `game_server.exe`, переименованные `java.exe`. Аргументы лаунчер берёт из строки `start /b …` в `startLoginServer.bat` и `startGameServer.bat`, так что правки в батниках учитываются. Рабочие папки — `server\login` и `server\game`.
3. Остановка логина и гейма — тем же Ctrl+C, что у Mobius. `GameServer` регистрирует shutdown-хук (`Shutdown`), то есть мир при Ctrl+C сохраняется. У логина хука нет, ему сохранять нечего. Сам La2offline гасил гейм через телнет (`shutdown`).
4. Запросы к базе (онлайн, персонажи, права GM) идут через клиент MariaDB: `--skip-ssl --default-character-set=utf8`, потому что utf8mb4 MySQL 5.0 не знает.
5. Логи — `log\java0.log.0` и `log\error0.log.0`: у L2J 2.0.6 ротация на пять файлов, текущий — `.0`.
6. Настройки — те же экраны. Схема строится из `*.properties`: формат комментариев тот же, умолчания подписаны «По умолчанию:», рамки разделов — строки из `=`. У GF 909 ключей в 21 файле. Пароли (`Password`, `StatusPW` телнета) не выгружаются.
7. Права GM — уровни этой сборки из профиля (`accessLevels`): 0 — игрок, 1 — Admin, 127 — Master (`MasterAccessLevel`). La2offline выдавал 127.
8. Клиент — `<игры>\Lineage II\La2system\L2.exe`. `l2.ini` там зашифрован ключом комьюнити, внутри `ServerAddr=127.0.0.1`. Протокол клиента в профиль не вписан, пока не проверен; сервер принимает 83–183.

### Что поменяно в копии

Только локальный режим, как у High Five. Бэкап до правок — `data/backups/config/gracia_final/2026-10-18_17-20-58/`.

- `login/config/loginserver.properties`: `LoginserverHostname` и `LoginHostname` — `127.0.0.1` вместо `*`;
- `game/config/server.properties`: `GameserverHostname` — `127.0.0.1` вместо `*`;
- `game/config/telnet.properties`: `EnableTelnet = False`. Это телнет-консоль гейма на порту 23 с паролем `root`: лаунчеру она не нужна, а слушала все сети.

`ExternalHostname = 209.25.140.17` (адрес для внешних клиентов, остался от прошлой сети) не тронут: клиент с этого ПК получает внутренний адрес. Геодата в сборке выключена (`GeoData = 0`, файлов нет), как в оригинале.

### Живая проверка 2026-10-18

High Five перед проверкой остановлен штатно, логин 2106 у хроник общий. Проверка через `python -m l2hub.cli`:

- **Старт** — база, логин и гейм за 15–20 секунд, гейм зарегистрирован на логине как `Server 1: Bartz`.
- **MySQL из ThinApp** работает на Windows 11 и пишет в песочницу копии: появились `<имя ПК>.err` и `<имя ПК>.pid`, `ibdata1` копии обновился. У оригинала `ibdata1` и `ib_logfile0` с тем же временем, что до проверки (2026-07-04 11:04:19). `%APPDATA%\Thinstall` не создан.
- **Первый старт MySQL** шёл с crash recovery («Database was not shut down normally»): La2offline гасил базу через `taskkill /F`. Восстановилась успешно. После штатной остановки следующий старт прошёл без recovery.
- **Порты** слушают только 127.0.0.1: 3305, 2106, 9014, 1042. Телнета на 23 нет.
- **Клиент MariaDB 13 с MySQL 5.0** работает: онлайн, список персонажей, права GM. Персонаж автора — LLIaJIaBa, 42 уровень, Master (127), аккаунт `123`.
- **Java 6 (32 бита)**: куча после старта — 375 из 1016 МБ.
- **Штатная остановка** — 27 секунд. Гейм по Ctrl+C пишет «SIGTERM received», сохраняет мир («Data saved. All players disconnected»), MySQL — «Normal shutdown … Shutdown complete». Процессов не остаётся.
- **Клиент** `La2system\L2.exe` запускается из лаунчера. Автор зашёл в мир персонажем, всё на месте.

Бэкап базы GF — zip папки данных MySQL целиком (`l2rt_<время>_<метка>.zip`, около 10 МБ), только пока база выключена; откат проверен, подробности — `docs/PLAN.md`, запись о бэкапах базы.

Известная проблема самой сборки, была и до нас: в базе нет таблицы `mods_wedding`. Гейм при старте пишет SEVERE от `CoupleManager`, свадьбы (`AllowWedding = True`) не работают.

Запасной путь на случай, если ThinApp когда-нибудь откажет, — перенести базу `l2rt` в нашу MariaDB. У старого драйвера `mysql-connector-java-5.1.8` с MariaDB 13 свои риски (`tx_isolation`, строгий `sql_mode`).
