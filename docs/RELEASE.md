# Публичный релиз L2Hub

Создан 2026-10-20. План, ничего не сделано. Решения автора — `docs/PLAN.md`, раздел «Решения», 2026-10-20; вопросы по выкладке репозитория — `docs/GITHUB.md`.

## Решено

- Открытый репозиторий на GitHub с релизами (установщик и портативный zip).
- Интерфейс на русском и английском.
- Ни от чего не отказываемся. Ненаш контент (клиенты, чужие системы, La2offline, тайлы карты, геодата) не раздаём: пользователь приносит своё или скачивает из источника сам, по кнопке. В репозитории и в релизе — только наше и то, что можно распространять.

## Главный принцип

L2Hub — однокнопочное приложение для новичков: нажал «Играть» и играешь. Раздавать клиенты и системы мы не можем, поэтому на пользователе ровно одно действие — достать клиент. Обычно его и так качают с сайта какого-нибудь сервера, целиком и сразу с системой под приватные серверы. Всё остальное делает лаунчер (согласовано с автором 2026-10-20):
- сам ищет клиенты по дискам (`L2.exe` или `L2.bin` рядом с `system`) и определяет хронику по протоколу — без «укажи папку»;
- сам проверяет систему: ключ комьюнити или `-INI=` — дальше сам; система с чужой защитой (Strix, SmartGuard и подобные) — «эта не пойдёт, нужна чистая»; голая система NCSoft на H5 — «нужна система под приватные серверы»;
- клиента нет — «Какую хронику хочешь?» и страница «что искать»: версия, протокол, система без защиты;
- систему для H5 пользователь перетаскивает архивом в окно: лаунчер распаковывает её в отдельную папку, осматривает и ставит в клиент с бэкапом;
- C4 — клиент L2Solo по их ссылке одним щелчком (их раздача, не наша);
- Essence и Classic — проверить живой клиент из официального лаунчера 4game: если его протокол совпадёт со сборкой Mobius, клиент законный и без чужих файлов.

## Что мешает сейчас

- ~~`launcher/l2hub/paths.py` считает всё от корня репозитория~~ — с 0.4.13 программа и данные раздельно: `APP` — ресурсы программы (патчи, фантомы, скрипты, доки; в exe — папка рядом с ним), `HOME` — данные (`runtime/`, `servers/`, `data/`, `profiles/`): переменная `L2HUB_HOME`, иначе у собранного exe — `%LOCALAPPDATA%\L2Hub\settings.json` (`{"home": "C:\\L2Hub"}`, пишет установщик), а из исходников — всегда корень репозитория (установленный L2Hub его не уводит); проверка «латиница без пробелов» — `paths.check_home`. От репозитория пока считают `scripts/*.ps1` и `tools/` — их заменит сборка из Python (шаг 2).
- Профили смотрят на папки клиентов автора (`<игры>\LA2 H5` и другие).
- Рантаймы — JDK 27, MariaDB, Ant (около 660 МБ) — положены руками. C4 требует git, Node и npm.
- ~~Исходники Mobius берутся со свежего `master`~~ — закреплены коммиты: `launcher/l2hub/mobius_pins.json` (SHA из комментария zip, который пишет GitLab), `cli fetch <id>` / `builder.fetch_sources` качает архив одной папки хроники по SHA и сверяет его. Проверено 2026-10-21: Interlude по закреплённому SHA совпал с архивом автора файл в файл (19 144 файла). Сменить коммит — только с `tools/phantoms_glue.py --check` и сборкой.
- ~~Базу создаёт `scripts/db_init.ps1`, сборку — `scripts/server_build.ps1`~~ — с 0.4.19 то же умеет `launcher/l2hub/builder.py` (`cli dbinit`, `cli build <id>`, `cli setup <id>`; кнопка «Пересобрать» в окне — уже через него): без PowerShell, 7-Zip и git, патчи накладываются байт в байт без преобразования строк. Сверено 2026-10-21: на чистых архивах Mobius дерево после модуля и патчей совпадает с `git apply` из репозитория по каждому файлу; свежая установка Interlude в отдельной папке данных (чистый архив → сборка → `dbinit` → `setup` → старт) поднялась с пустым `error0.log`. Скрипты `scripts/*.ps1` остаются для ручной работы агентов.
- ~~Конфиги из патчей и модуля фантомов в развёрнутый сервер кладём руками~~ — с 0.4.237 их выкладывает сборка (`builder.deploy_configs`; у `scripts/server_build.ps1` — через `cli deploy-configs`). Что выложила прошлая сборка, помнит `servers/<id>/.config_base/` — копия конфигов архива (`game/config`, `login/config`). По ней каждый конфиг нового архива:
  - в сервере нет — копируется;
  - в сервере как в прошлой сборке (или как после любого из ранних патчей стопки) — его не правили, заменяется целиком;
  - `.ini`, который правили (окно «Настройки сервера», выключатели, руками), сливается по ключам (`configs.merge_ini`):
    - недостающий ключ дописывается с комментарием над ним из сборки, после соседнего ключа;
    - значение, которое в сервере как в прошлой сборке, берётся из новой;
    - значение, которое в сервере меняли, остаётся, даже если сборка его тоже поменяла (такие ключи сборка называет в журнале);
    - ключи, которых в сборке больше нет, и всё прочее в файле не трогаются;
  - `.xml` и прочие, которые правили, а сборка тоже поменяла, остаются как есть; версия сборки ложится в `servers/<id>/.config_new/<путь>` для ручного переноса;
  - `hexid.txt` — не настройка, его пишет гейм: не трогается.

  Перед записью — копия файла в `data/backups/config/<id>/<время>_build/`. У сервера, собранного до 0.4.237, записи нет. Первая пересборка берёт за прошлую сборку прошлый архив (`servers/<id>/build/<сборка>.zip` до Ant) и называет в журнале расхождения в наших конфигах. В остальных конфигах Mobius отличия от архива — заведомо правки сервера: пароль базы, адреса, выключатели. Проверено 2026-10-24 в `L2Hub_rttest` на Classic и High Five:
  - сборка с нуля — сервер равен архиву байт в байт (7768 и 25 771 файл);
  - пересборка поверх правок выключателями и руками — в сервере ни байта не изменилось;
  - синтетическая «следующая сборка» на настоящих конфигах Classic: новый ключ лёг после соседа, нетронутое значение пришло из сборки, правка руками и выключатель остались, нетронутый `NPC.ini` заменён целиком, правленый `ClassMaster.xml` остался, его версия сборки — в `.config_new`, в `Rates.ini` вне своих строк — байт в байт;
  - сервер без записи с прошлым архивом — то же.
- ~~Пересборка после обновления программы падала~~ — сделано 2026-10-30. Что уже наложено, сборка узнаёт, снимая патчи стопки с конца. Если патч или врезки изменились с прошлой сборки, в дереве лежит их прошлая версия: новая не снимается и не накладывается, а следом не снимаются и ранние патчи того же файла. «Пересобрать» падала с «Патч не наложился» (`0002-champion-tiers` у Interlude и High Five, найдено первым запуском кнопки в `L2Hub_rttest`). Теперь при таком сбое `builder.server_build` зовёт `reset_sources`: дерево исходников снова как в архиве на закреплённом коммите, всё, что от него отличалось, — копией в `servers/<id>/.module_overwritten/<время>_before_reset`, затем модуль и вся стопка заново; архив, если его нет, скачивается. Не легло и на чистое дерево — ошибка, как раньше. Проверено в `L2Hub_rttest`: Interlude со сборкой 2026-10-22 — `cli build`, High Five со сборкой 2026-10-24 — кнопкой в окне; обе сборки прошли, модуль «совпадает», серверы после неё не запускались. Не закрыто: патч, убранный из стопки, не падает и остаётся в дереве, пока не помешает другому; `scripts/server_build.ps1` так не умеет.
- ~~Серверы запускаются в дереве процессов окна~~ — разобрано 2026-10-21: смерть родителя на Windows детей не убивает, их убивает только job-объект с `KILL_ON_JOB_CLOSE`. У лаунчера из venv такой job у трамплина uv, но с `SILENT_BREAKAWAY_OK` — серверы из него выходят сами и переживают окно; у собранного exe job нет. Остаётся консоль агента: job приложения Claude выход запрещает (`CREATE_BREAKAWAY_FROM_JOB` — `WinError 5`), поэтому сервер из консоли агента гаснет вместе с приложением — это только для проверок агентом (`AGENTS.md`).

## Хроники в публичной версии

Кто что приносит. Сервер Mobius лаунчер скачивает и собирает сам, с нашими модами. Клиент — всегда у пользователя. Система клиента под приватный сервер нужна там, где штатную систему NCSoft не направить на свой адрес или не запустить без старого античита GameGuard.

| Хроника | Сервер | Клиент | Система клиента |
|---|---|---|---|
| Interlude, Gracia Epilogue | Mobius — лаунчер | свой | своя, из репака под приватные серверы: уже на `127.0.0.1` или `l2.ini` на ключе комьюнити — лаунчер перешифровывает его сам |
| High Five | Mobius — лаунчер | свой | своя, под приватные серверы (у автора — R.C-TEAM): штатная NCSoft без GameGuard не работает (ниже) |
| Essence, Classic | Mobius — лаунчер | свой, официальный 4game | не нужна: штатный `L2.exe -INI=.\L2Hub.ini`, Frost выключается строкой `FrostModule=false` |
| C4 | L2Solo — лаунчер | клиент L2Solo (их ссылка; GameGuard в нём выключен лоадером, `docs/L2SOLO.md`) | в их клиенте |
| Gracia Final | свой La2offline — бонус (решение автора 2026-10-20) | свой | `La2system` из La2offline |
| Хроники без Mobius (Kamael, Hellbound, Gracia 1–2, GoD и другие) | своя сборка L2J — импорт (ниже) | свой | своя |

Gracia Final: публичных исходников сборки GF не нашлось, La2offline в сети уже нет; ближайшая хроника с исходниками, фантомами и модами — Gracia Epilogue. Основные хроники публичной версии — Interlude, High Five, Gracia Epilogue, C4, Classic, Essence.

### Штатная система NCSoft для High Five (проверено 2026-10-20)

`<игры>\LA2 H5\system_ncsoft`: `L2.ini` на ключе NCSoft, `ServerAddr=L2authd.Lineage2.com`, обычное окно входа (`ExternalLogin=false`), вместо `L2.exe` — `L2.bin`, протокол 267 (из краш-репорта: `LS1(267)`), заставка Freya. С разрешения автора положили открытый `L2Hub.ini` (правки как у `tools/l2ini_plain.py`, `FrostModule` в H5 нет) и запустили `L2.bin -INI=.\L2Hub.ini`:
- первый запуск — падение `sizeof(*this)==GetClass()->GetPropertiesSize()` в `UGameEngine::Init`: `Paths=../System/*.u` у автора ведёт в соседнюю `system` с файлами R.C-TEAM, а `Engine.dll` — из NCSoft. С путями на `../system_ncsoft/` клиент дошёл до окна входа: `-INI=` работает и на движке H5. У пользователя с одной системой в `system` этой проблемы нет;
- на окне входа — «The GameGuard file is damaged. Please reinstall GameGuard. (ErrorCode=153)», после «Confirm» клиент закрывается. Рубильника в ini у GameGuard нет: его выключают только пропатченные бинарники — это и есть системы комьюнити. Свой обход античита не делаем.

Итог: для High Five пользователь приносит систему под приватные серверы. Запасной путь через `hosts` (`127.0.0.1 L2authd.Lineage2.com`) упирается в тот же GameGuard. `L2Hub.ini` после проверки убран в Корзину, клиент автора — как был.

### Импорт своей сборки (идея автора 2026-10-20)

**Сделано (2026-10-21):** «Подключить свою сборку» для любой хроники, виды — данными в `launcher/l2hub/bundles.json`: `"runtime": "own"` — сборка-комбайн со своей базой и Java (La2offline), `"runtime": "ours"` — сборка на нашей Java и MariaDB. Первый вид «ours» — готовый сервер L2J Mobius (своя или чужая сборка): копия, проверка версии Java по байткоду jar (`builder.jar_java` против нашей JDK; новее — отказ), своё имя базы, если занято, заливка SQL и локальный режим (`builder.server_setup`), профиль `"type": "mobius"` с `"source"`. Проверено: сборка Interlude из `build/` подключена к хронике C2 в отдельной папке данных — база `l2hub_c2`, сервер поднялся, гейм зарегистрирован. Папку можно указать на уровень выше сборки. Второй вид «ours» — **L2JLisvus** (C4, GPL-3.0, разведка и рецепт c4-interlude — `docs/C4_EMULATORS.md`) — без единой строки кода под него, только описанием: части `gameserver/` (при копии становится `game/`) и `login/`, конфиги `*.properties` (имена — `files` вида), запуск на нашей Java по `main`-классу и classpath (`parts`), база — наша MariaDB (`database`: URL, логин, пароль, все `sql/*.sql`), ключи локального режима (`local`), лог `java0.log.0`. Проверено 2026-10-21 в отдельной папке данных: C4 с нуля — 80 таблиц в `l2hub_c4`, логин и гейм на 127.0.0.1, гейм зарегистрирован («Server 1: Bartz»), протокол 656–665 (клиент L2Solo подходит), остановка Ctrl+C с сохранением мира («SIGTERM received»). Ядро для этого обобщено: `servers.own_db` (своя база — только у комбайнов), `servers.config_file` (имена `*.properties` из вида).

Сборки семейства L2J устроены одинаково, поэтому «принеси свою сборку» можно сделать правилами, без LLM:
- опознать сборку: jar и `.bat` запуска, главные классы логина и гейма; версию Java — по версии байткода в jar (старым сборкам — Java 6–8);
- конфиги: ключи базы, портов и адреса (`URL`, `Login`, `Password`, `LoginserverPort`, `GameserverPort`, `ExternalHostname`, `AutoCreateAccounts`, `AcceptNewGameServer` и аналоги у разных семейств) переписать на свои, остальные настройки сборки — как есть;
- база: SQL сборки — в пустую базу, старый синтаксис MySQL 5 — правилами (`TYPE=MyISAM` → `ENGINE=`, нулевые даты, кодировки); регистрация гейм-сервера (hexid);
- клиент: протокол, сверка с сервером, адрес — как в таблице выше;
- запуск и разбор типовых ошибок по таблице правил (`ClassNotFound` — не та Java, `Access denied` — пароль базы, `Table doesn't exist` — не залит SQL, `Address in use` — занят порт); что правила не узнали — лог пользователю.

Не берёмся: закрытые платные сборки с лицензией и привязкой к железу; L2OFF (утёкший сервер NCSoft на C++ и MSSQL); сборки без SQL или датапака и со своими лаунчерами — только с подсказкой по логу.

## Подпись

Без подписи Windows при первом запуске показывает SmartScreen («Windows защитила ваш компьютер»), антивирусы чаще ругаются на exe PyInstaller. Работать это не мешает.

[SignPath Foundation](https://signpath.org/) бесплатно подписывает открытые проекты. Условия ([signpath.org/terms](https://signpath.org/terms)):
- лицензия OSI (GPL-3.0 подходит), без проприетарных компонентов;
- проект уже выпущен в том виде, который подписывается, — первый релиз всё равно без подписи;
- сборка автоматическая, из репозитория (GitHub Actions);
- политика подписи опубликована на странице проекта; каждый запрос на подпись подтверждается вручную;
- SignPath — издатель сертификата и может приостановить подписку при нарушении их правил. Лаунчер эмулятора коммерческой игры — серая зона, отказ возможен.

Сроки рассмотрения SignPath не публикует.
